# redshift_role_grant (Resource)

Grants one role to a receiving role or database user. For example, a group role can inherit `sys:dba`, while Grafana's
database user can inherit `sys:monitor`. A user can also receive the role `WITH ADMIN OPTION` to grant it to others.
See AWS [GRANT ROLE](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html#grant-roles) and
[REVOKE ROLE](https://docs.aws.amazon.com/redshift/latest/dg/r_REVOKE.html#revoke-roles).

```sql
GRANT ROLE role TO ...;
REVOKE ROLE role FROM ...;
REVOKE ADMIN OPTION FOR ROLE role FROM ...;
```

## Example Usage

```terraform
resource "redshift_role_grant" "operators" {
  role    = "sys:dba"
  to_role = redshift_role.operators.name
}

resource "redshift_role_grant" "grafana" {
  role    = "sys:monitor"
  to_user = redshift_user.grafana.name
}

# The team lead may grant the readers role to other users and roles.
resource "redshift_role_grant" "team_lead" {
  role         = redshift_role.readers.name
  to_user      = redshift_user.team_lead.name
  admin_option = true
}
```

## Schema

### Required

- `role` (String) Role being granted, including built-in `sys:` roles. Changing it replaces the grant.

### Optional

- `admin_option` (Boolean) Whether the receiving user holds the role `WITH ADMIN OPTION` and can grant it to other users and roles (`svv_user_grants.admin_option`). Only users hold the admin option, so `true` requires `to_user`. Defaults to `false`; changes are applied in place and keep the membership.
- `to_role` (String) Receiving role; exactly one of `to_role` and `to_user` is required. Changing it replaces the grant.
- `to_user` (String) Receiving database user; exactly one of `to_role` and `to_user` is required. Changing it replaces the grant.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.
<!-- markdownlint-enable MD013 MD022 MD033 -->

Specify exactly one of `to_role` and `to_user`. `admin_option = true` requires `to_user`, because Redshift documents
`WITH ADMIN OPTION` only for user recipients. Redshift documents no other recipient for roles: the role syntax lists no
`GROUP`, and `PUBLIC`, which the parameter text mentions, appears in neither the `GRANT` nor the `REVOKE` syntax and
has no catalog view to verify it.

## Lifecycle and Ownership

Deletion revokes only this relationship, together with its admin option.

## Reconciliation

Refresh reads the grant from `SVV_USER_GRANTS`, including `admin_option`, for a user recipient, or from
`SVV_ROLE_GRANTS` for a role recipient; an update changes only the admin option and re-reads the catalog to verify the
result; every other change replaces the grant. Creation runs `GRANT ROLE ... TO`, with `WITH ADMIN OPTION` when
configured, and deletion runs `REVOKE ROLE ... FROM`.

| Change                                                  | Result                                                                                       |
|---------------------------------------------------------|----------------------------------------------------------------------------------------------|
| `role`                                                  | replaces the grant: `REVOKE ROLE` for the old role and `GRANT ROLE` for the new one          |
| `to_role` or `to_user`, including a switch between them | replaces the grant: `REVOKE ROLE` from the old recipient and `GRANT ROLE` to the new one     |
| `admin_option` set to `true`                            | `GRANT ROLE ... TO ... WITH ADMIN OPTION`, which keeps the membership; refused for `to_role` |
| `admin_option` set to `false` or removed                | `REVOKE ADMIN OPTION FOR ROLE ... FROM`, which keeps the membership                          |

**Drift.** A grant revoked outside Terraform, or whose role or recipient was dropped, is removed from state, and the
next plan grants it again. For a user recipient, an admin option granted or revoked outside Terraform is set back with
the statements above; the user holds it when any grantor's grant carries it. A role recipient always records `false`.
Other grants of the role are never read.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_role_grant.operators
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "admin"
    role           = "sys:dba"
    to_role        = "ncidc:analytics-operators"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_role_grant.operators \
  '{"workgroup_name":"warehouse","database":"admin","role":"sys:dba","to_role":"ncidc:analytics-operators"}'
```

To import Grafana's role grant, use `"role":"sys:monitor","to_user":"grafana"` in the JSON identity. The next refresh
reads the admin option.
