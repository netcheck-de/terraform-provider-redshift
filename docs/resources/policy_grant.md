# redshift_policy_grant (Resource)

Owns `SELECT` on one lookup table for one row-level security (`RLS`) or dynamic data masking (`MASKING`) policy, which a
policy needs when its expression reads the table. See AWS
[GRANT](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html#grant-row-level-security) and
[REVOKE](https://docs.aws.amazon.com/redshift/latest/dg/r_REVOKE.html#revoke-role-level).

## SQL Statements

```sql
GRANT SELECT ON TABLE ... TO { RLS | MASKING } POLICY policy_name;
REVOKE SELECT ON TABLE ... FROM { RLS | MASKING } POLICY policy_name;
```

## Example Usage

```terraform
# The masking expression reads a lookup table, which the policy itself needs SELECT on.
resource "redshift_policy_grant" "exempt_lookup" {
  database_name = redshift_masking_policy.email.database
  schema_name   = "public"
  object_name   = "masking_exempt_emails"
  policy_type   = "MASKING"
  policy_name   = redshift_masking_policy.email.name
  privileges    = ["SELECT"]
}
```

## Schema

### Required

- `database_name` (String) Local database that holds the lookup table and the policy. Changing it replaces the grant.
- `object_name` (String) Lookup table that the policy's expression reads. Changing it replaces the grant.
- `policy_name` (String) Policy that receives the permission. Changing it replaces the grant.
- `policy_type` (String) `RLS` for a row-level security policy or `MASKING` for a dynamic data masking policy. Changing it replaces the grant.
- `privileges` (Set of String) Privileges Terraform grants: `["SELECT"]`, the only permission a policy can hold, or empty to revoke it. Redshift does not report grants to policies, so this records what Terraform applied and does not detect changes made outside Terraform.
- `schema_name` (String) Schema of the lookup table. Changing it replaces the grant.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

## Lifecycle and Ownership

`privileges` accepts only `SELECT`. Before each change the resource checks that the database, schema, table, and
policy exist (`SVV_RLS_POLICY` or `SVV_MASKING_POLICY`). Deleting the resource revokes the grant. Policies cannot hold
grant options.

**Redshift does not report grants to policies.** The AWS reference lists only users, roles, groups, and `PUBLIC` as the
identities that [SHOW GRANTS](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_GRANTS.html) and
[SVV_RELATION_PRIVILEGES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_RELATION_PRIVILEGES.html) return, so
the provider cannot read the grant back, and state records what Terraform granted; see
[Reconciliation](#reconciliation). For the same reason there is no `redshift_policy_grant` data source.

## Reconciliation

Refresh checks only that the database, schema, lookup table, and policy exist and keeps the recorded `privileges`; an
update runs `GRANT` or `REVOKE` for the difference between the recorded and the configured `privileges` and cannot
re-read the result; every change to the tuple itself replaces the grant.

| Change                                           | Result                                                                                                                                                       |
|--------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `database_name`, `schema_name`, or `object_name` | replaces the grant: they name another lookup table, so the recorded privileges on the old table are revoked and the configured ones granted on the new table |
| `policy_type` or `policy_name`                   | replaces the grant: they name another policy                                                                                                                 |
| `privileges` set to `["SELECT"]`                 | `GRANT SELECT ON TABLE ... TO RLS POLICY ...` or `TO MASKING POLICY ...`                                                                                     |
| `privileges` set to `[]`                         | `REVOKE SELECT ON TABLE ... FROM RLS POLICY ...` or `FROM MASKING POLICY ...`                                                                                |

A create grants the configured `privileges` without comparing them with anything, and a deletion revokes the recorded
ones; see [Import](#import) for imported grants.

**Drift.** The grant itself is never read back: a grant revoked or added outside Terraform is not detected, and the next
plan shows no change. Change `privileges` or replace the resource to apply it again. A missing database, schema, lookup
table, or policy removes the grant from state, and the next plan creates it again.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_policy_grant.exempt_lookup
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "admin"
    database_name  = "warehouse"
    schema_name    = "public"
    object_name    = "masking_exempt_emails"
    policy_type    = "MASKING"
    policy_name    = "mask_email"
  })
}
```

The example binds a Serverless workgroup. Replace `workgroup_name` with `cluster_identifier` for a provisioned
cluster, or with `endpoint` (`host:port`) for a direct password connection; see
[connection methods](../guides/connection_methods.md#imports-and-transport-switching).

Alternatively, use `terraform import`:

```shell
terraform import redshift_policy_grant.exempt_lookup \
  '{"workgroup_name":"warehouse","database":"admin","database_name":"warehouse","schema_name":"public","object_name":"masking_exempt_emails","policy_type":"MASKING","policy_name":"mask_email"}'
```

Import cannot read the grant, so the imported state records no privileges and the next apply runs `GRANT` for the
configured ones.
