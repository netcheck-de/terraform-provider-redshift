# redshift_datashare_membership (Resource)

Exclusively manages all current tables/views or SQL functions in a producer datashare schema. This is an authoritative
schema-and-kind owner, not a creation-time snapshot. See AWS
[ALTER DATASHARE](https://docs.aws.amazon.com/redshift/latest/dg/r_ALTER_DATASHARE.html).

## SQL Statements

```sql
ALTER DATASHARE datashare ADD ALL TABLES IN SCHEMA schema;
ALTER DATASHARE datashare ADD ALL FUNCTIONS IN SCHEMA schema;
ALTER DATASHARE datashare REMOVE ALL TABLES IN SCHEMA schema;
ALTER DATASHARE datashare REMOVE ALL FUNCTIONS IN SCHEMA schema;
```

## Example Usage

```terraform
resource "redshift_datashare_membership" "functions" {
  database  = redshift_datashare_schema.reporting.database
  datashare = redshift_datashare_schema.reporting.datashare
  schema    = redshift_datashare_schema.reporting.schema
  kind      = "FUNCTIONS"
  all       = true

  # The shared schema must have include_new = false. Do not manage the same kind with per-object members or grants.
  depends_on = [redshift_function.greater]
}
```

## Schema

### Required

- `all` (Boolean) Must be true to acknowledge exclusive ownership. Refresh reports false when any current source object of this kind is not shared; the next apply adds all current objects. An empty schema is fully covered.
- `database` (String) Local producer database.
- `datashare` (String) Producer datashare name.
- `kind` (String) TABLES includes tables and views; FUNCTIONS includes SQL UDF overloads. Exclusive ownership covers this whole kind in the share/schema.
- `schema` (String) Schema already included in the share, with include_new = false. Periods in schema or source member names are unsupported because the membership catalog does not quote qualification.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

## Lifecycle and Ownership

Every managed refresh and mutation requires a SQL superuser. Before reading the producer's catalogs, the provider
queries `pg_user.usesuper` for `current_user` in the provider administration database. A false, missing, malformed, or
failed result is an error: existing state is retained and no membership mutation runs. This full-visibility prerequisite
prevents a restricted identity's empty or hidden catalogs from proving coverage or being mistaken for a deleted parent.
Because the check uses the administration database, a genuinely dropped producer database can still be removed from state.

`all = true` explicitly acknowledges ownership of every current member of the selected kind in the share/schema.
Create and Update add all current source objects. Destroy removes all current memberships of that kind, including
ones added outside Terraform since creation or import. Source tables, views, functions, the schema membership, and
members of the other kind are not removed. An empty source schema is fully covered.

Only one owner may manage a share/schema/kind tuple. Do not combine this resource with `redshift_datashare_table`,
another bulk owner, manual membership management, or overlapping scoped grants for the selected kind. TABLES and
FUNCTIONS owners may coexist for the same schema because their kinds do not overlap. Import adopts the entire kind;
it does not recover a historical snapshot. Overlap with other Terraform states or provider aliases cannot be detected.

The shared schema must have `include_new = false`. Every mutation verifies this setting and refuses to proceed while
it is true. Future objects are deliberately not added automatically: refresh detects missing coverage, and apply
runs `ADD ALL` again. Declare dependencies on the source objects to create them before the bulk membership is applied.
Run Terraform after creating objects outside Terraform to add those objects to the share.
When adding source objects to an already managed schema in the same Terraform configuration, run another plan/apply
after their creation: refresh cannot observe source objects that do not exist yet, and a dependency alone does not
schedule an unchanged membership owner for Update.

Refresh compares local source catalogs with `SVV_DATASHARE_OBJECTS`. For SQL functions, the membership catalog reports
identical unqualified-overload rows for overloaded names. Counts per qualified name prove coverage of every overload
without pretending to identify a particular overload. Schema or source member names containing periods are rejected
because catalog qualification is not quoted
and cannot be unambiguously matched. External tables and non-SQL functions are outside this resource's ownership.

## Reconciliation

Refresh retains the parent tuple when coverage is incomplete and sets `all` to false; the next apply restores it with
`ALTER DATASHARE ... ADD ALL ... IN SCHEMA`. Identity changes replace the exclusive owner.

| Change      | Result                                                                                            |
|-------------|---------------------------------------------------------------------------------------------------|
| `database`  | replaces the exclusive owner, removing its old kind memberships before adding the new ones        |
| `datashare` | replaces the exclusive owner, removing its old kind memberships before adding the new ones        |
| `schema`    | replaces the exclusive owner, removing its old kind memberships before adding the new ones        |
| `kind`      | replaces the exclusive owner, removing the old kind memberships before adding the new kind        |
| `all`       | must be true; drift to false runs `ALTER DATASHARE ... ADD ALL ... IN SCHEMA` to restore coverage |

**Drift.** Missing memberships and newly created unshared source objects change `all` to false instead of removing
the resource from state. A missing producer database, share, or schema membership removes the owner from state.
Objects newly added to the share by another actor remain owned by this exclusive resource and are removed on destroy.
Enabling `include_new` produces a refresh warning and blocks subsequent mutations until it is disabled.

For example, after another SQL overload is created, refresh observes incomplete FUNCTIONS coverage. The next apply
adds every current SQL overload:

```sql
ALTER DATASHARE "producer" ADD ALL FUNCTIONS IN SCHEMA "serving";
```

## Import

Use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_datashare_membership.functions
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "analytics"
    datashare      = "reporting"
    schema         = "reporting"
    kind           = "FUNCTIONS"
  })
}
```

The example binds a Serverless workgroup. Replace `workgroup_name` with `cluster_identifier` for a provisioned
cluster, or with `endpoint` (`host:port`) for a direct password connection; see
[connection methods](../guides/connection_methods.md#imports-and-transport-switching).

Alternatively, use `terraform import`:

```shell
terraform import redshift_datashare_membership.functions \
  '{"workgroup_name":"warehouse","database":"analytics","datashare":"reporting","schema":"reporting","kind":"FUNCTIONS"}'
```

Import acknowledges ownership of every member of the selected kind, not just the memberships originally added in bulk.
