# redshift_column_grant (Resource)

Owns the exact column-level privileges of one grantee on one table, view, or materialized view: which columns hold
`SELECT` and which hold `UPDATE`. See AWS [GRANT](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html#grant-column-level)
and [REVOKE](https://docs.aws.amazon.com/redshift/latest/dg/r_REVOKE.html#revoke-column-level).

```sql
GRANT privilege (column, ...) ON TABLE database_name.schema_name.object_name TO ...;
REVOKE privilege (column, ...) ON TABLE database_name.schema_name.object_name FROM ...;
```

Columns that are no longer configured are revoked first, then missing columns are granted, with one statement per
privilege. Deleting the resource revokes the column privileges it owns.

## Example Usage

```terraform
resource "redshift_column_grant" "events" {
  database_name = "analytics"
  schema_name   = "reporting"
  object_name   = "events"
  grantee       = redshift_role.analysts.name
  grantee_type  = "ROLE"
  privileges = {
    SELECT = ["id", "label", "created_at"]
    UPDATE = ["label"]
  }
}
```

## Schema

### Required

- `database_name` (String) Local database containing the table or view. Changing it replaces the grant.
- `grantee` (String) Receiving identity name; use `public` for `PUBLIC`. Changing it replaces the grant.
- `grantee_type` (String) `ROLE`, `USER`, `GROUP`, or `PUBLIC`. Changing it replaces the grant.
- `object_name` (String) Table, view, or materialized view whose columns are granted; late-binding views do not support column privileges. Changing it replaces the grant.
- `privileges` (Map of Set of String) Exact explicit column privileges: a map from `SELECT` or `UPDATE` to the set of column names that hold it. Views accept only `SELECT`. Column names are quoted; write them as the catalog stores them, which is lower case unless `enable_case_sensitive_identifier` is on. An empty map revokes every column privilege of this tuple; updated in place.
- `schema_name` (String) Schema containing the table or view. Changing it replaces the grant.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

All identity arguments require replacement when changed; `privileges` updates in place. One resource owns all columns
of one grantee on one relation, because `SVV_COLUMN_PRIVILEGES` reports each column, privilege, and grantee exactly.
Column names are quoted identifiers, so write them as the catalog stores them (lower case unless case-sensitive
identifiers are enabled).

## Lifecycle and Ownership

The resource checks that the grantee, the local database, and the relation exist, then reads
[SVV_COLUMN_PRIVILEGES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_COLUMN_PRIVILEGES.html) in that database.
It applies the difference and re-reads the catalog to verify convergence. A missing grantee, database, or relation
removes the resource from state.

Redshift's [column-level usage notes](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT-usage-notes.html#r_GRANT-usage-notes-clp)
apply:

- Only the table owner or a superuser can grant column privileges, and `WITH GRANT OPTION` is not supported, so the
  resource has no `grant_option_privileges`.
- Views accept only `SELECT`; late-binding views do not support column privileges.
- A grantee cannot hold the same privilege at table and column level. While a table-level grant (for example from
  `redshift_object_grant`) exists, a column grant has no effect and the resource reports that it did not converge.
  Revoking the privilege at table level also revokes its column grants, which the next refresh shows as drift.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_column_grant.events
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "admin"
    database_name  = "analytics"
    schema_name    = "reporting"
    object_name    = "events"
    grantee        = "analysts"
    grantee_type   = "ROLE"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_column_grant.events \
  '{"workgroup_name":"warehouse","database":"admin","database_name":"analytics","schema_name":"reporting","object_name":"events","grantee":"analysts","grantee_type":"ROLE"}'
```
