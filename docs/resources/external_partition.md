# redshift_external_partition (Resource)

Manages one partition of a partitioned
[external table](https://registry.terraform.io/providers/netcheck-de/redshift/latest/docs/resources/external_table).
See AWS [ALTER TABLE](https://docs.aws.amazon.com/redshift/latest/dg/r_ALTER_TABLE.html) and
[Partitioning Redshift Spectrum external tables](https://docs.aws.amazon.com/redshift/latest/dg/c-spectrum-external-tables.html#c-spectrum-external-tables-partitioning).

```sql
ALTER TABLE schema.table ADD PARTITION (values...) LOCATION ...;
ALTER TABLE schema.table PARTITION (values...) SET LOCATION ...;
ALTER TABLE schema.table DROP PARTITION (values...);
```

## Example Usage

```terraform
resource "redshift_external_partition" "sales_2008_01" {
  database = redshift_external_table.sales.database
  schema   = redshift_external_table.sales.schema
  table    = redshift_external_table.sales.name
  values   = { sale_date = "2008-01-01" }
  location = "s3://example-bucket/tickit/sales/sale_date=2008-01-01/"
}
```

## Schema

### Required

- `database` (String) Local Redshift database holding the external schema. Changing it replaces the partition.
- `location` (String) `s3://` folder or manifest file holding the partition's data. Changes run `ALTER TABLE ... PARTITION (...) SET LOCATION`.
- `schema` (String) External schema of the table. Changing it replaces the partition.
- `table` (String) Partitioned external table, for example a `redshift_external_table`. Changing it replaces the partition.
- `values` (Map of String) Partition value for every partition key of the table, keyed by partition key name, such as `{ saledate = "2008-01" }`. Statements list the keys in the table's partition-key order. Changing it replaces the partition.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

## Lifecycle and Ownership

Creation reads the table's partition keys from `svv_external_columns`, requires `values` to set each of them exactly
once (names compare without case), and runs `ADD PARTITION` without `IF NOT EXISTS`, so an existing partition is an
error rather than silently adopted. Statements list the keys in the table's partition-key order. A changed `location`
runs `PARTITION (...) SET LOCATION`; any other change replaces the partition. Deletion runs `DROP PARTITION`, which
removes only catalog metadata; the S3 data stays.

Refresh reads `svv_external_partitions`. The view drops a folder's trailing slash and truncates locations to 128
characters, so those forms of the configured location are not drift. A partition whose table, external schema, or
database is gone, or whose table no longer has the configured partition keys, is removed from state.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity. The `values` field holds the partition values as
a JSON-encoded string, because identity fields are strings:

```terraform
import {
  to = redshift_external_partition.sales_2008_01
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "warehouse"
    schema         = "raw"
    table          = "sales"
    values         = jsonencode({ sale_date = "2008-01-01" })
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_external_partition.sales_2008_01 \
  '{"workgroup_name":"warehouse","database":"warehouse","schema":"raw","table":"sales","values":"{\"sale_date\":\"2008-01-01\"}"}'
```

The location is read from the catalog on refresh.
