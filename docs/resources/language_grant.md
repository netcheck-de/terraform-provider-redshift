# redshift_language_grant (Resource)

Owns `USAGE` on one language in one local database for one grantee. `USAGE ON LANGUAGE sql` is required to create SQL
user-defined functions and `USAGE ON LANGUAGE plpgsql` to create stored procedures. See AWS
[GRANT](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html) and
[REVOKE](https://docs.aws.amazon.com/redshift/latest/dg/r_REVOKE.html).

```sql
GRANT USAGE ON LANGUAGE language_name TO ... [WITH GRANT OPTION];
REVOKE [GRANT OPTION FOR] USAGE ON LANGUAGE language_name FROM ...;
```

An empty `privileges` set revokes `USAGE`. Deleting the resource revokes what it owns.

## Example Usage

```terraform
# Stored procedure authors in the analytics database.
resource "redshift_language_grant" "procedures" {
  database_name = "analytics"
  language_name = "plpgsql"
  grantee       = redshift_role.developers.name
  grantee_type  = "ROLE"
  privileges    = ["USAGE"]
}

# A user who may create SQL UDFs and pass that right on.
resource "redshift_language_grant" "sql_udfs" {
  database_name           = "analytics"
  language_name           = "sql"
  grantee                 = redshift_user.udf_owner.name
  grantee_type            = "USER"
  privileges              = ["USAGE"]
  grant_option_privileges = ["USAGE"]
}

# Only the grantees above may create stored procedures: this revokes the built-in USAGE that PUBLIC holds.
resource "redshift_language_grant" "public_procedures" {
  database_name = "analytics"
  language_name = "plpgsql"
  grantee       = "public"
  grantee_type  = "PUBLIC"
  privileges    = []
}
```

## Schema

### Required

- `database_name` (String) Local database whose language privileges are managed; language privileges are per database. Changing it replaces the grant.
- `grantee` (String) Receiving identity name; use `public` for `PUBLIC`. Changing it replaces the grant.
- `grantee_type` (String) `ROLE`, `USER`, `GROUP`, or `PUBLIC`. Changing it replaces the grant.
- `language_name` (String) `sql` (SQL user-defined functions) or `plpgsql` (stored procedures). Changing it replaces the grant.
- `privileges` (Set of String) Exact explicit privilege set. An empty set revokes owned privileges.

### Optional

- `grant_option_privileges` (Set of String) Subset of `privileges` that the grantee also holds `WITH GRANT OPTION`, so it can grant them to others. Only a `USER` grantee can hold grant options. Defaults to none. Removing a privilege from this set keeps the privilege and revokes only its grant option; Redshift rejects that while the grantee's own grants depend on it, because the provider never cascades.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

All identity arguments require replacement when changed; `privileges` and `grant_option_privileges` update in place.
`plpythonu` is not supported, because Redshift no longer supports Python UDFs.

## Lifecycle and Ownership

The resource checks the grantee and the local database, then reads
[SVV_LANGUAGE_PRIVILEGES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_LANUGAGE_PRIVILEGES.html) in that
database, including `admin_option` for grant options. It revokes before it grants and re-reads the catalog to verify
convergence. A missing grantee or database removes the resource from state.

Redshift grants `USAGE` on `sql` and `plpgsql` to `PUBLIC` by default, and `SVV_LANGUAGE_PRIVILEGES` lists only
explicit grants, so the default may have no catalog row. To restrict who can create functions or procedures, manage the
`PUBLIC` tuple with an empty `privileges` set and grant `USAGE` to specific users, roles, or groups. Because the
default can be invisible, every create, update, and destroy of a `PUBLIC` tuple without `USAGE` sends
`REVOKE USAGE ON LANGUAGE ... FROM PUBLIC`, which changes nothing once the grant is gone. Importing such a tuple plans
no change, so create it instead of importing it. Destroying any `PUBLIC` tuple leaves `PUBLIC` without `USAGE`; the
default is never restored. To give it back, apply `privileges = ["USAGE"]`, then remove the resource with a `removed`
block whose `lifecycle { destroy = false }` keeps that grant.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_language_grant.procedures
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "admin"
    database_name  = "analytics"
    language_name  = "plpgsql"
    grantee        = "developers"
    grantee_type   = "ROLE"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_language_grant.procedures \
  '{"workgroup_name":"warehouse","database":"admin","database_name":"analytics","language_name":"plpgsql","grantee":"developers","grantee_type":"ROLE"}'
```
