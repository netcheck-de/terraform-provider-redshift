# redshift_datashare_privilege (Resource)

Owns the exact explicit `ALTER` and `SHARE` permissions that **one SQL identity** holds on a producer datashare.
`ALTER` lets the grantee add or remove objects and set `PUBLICACCESSIBLE`; `SHARE` lets it grant consumers usage. These
are the only datashare permissions Redshift grants to users, roles, and groups. See AWS
[GRANT](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html#grant-datashare-syntax) and
[REVOKE](https://docs.aws.amazon.com/redshift/latest/dg/r_REVOKE.html#revoke-datashare-permissions).

```sql
GRANT privilege ON DATASHARE datashare_name TO grantee;
REVOKE privilege ON DATASHARE datashare_name FROM grantee;
```

Consumer `USAGE` for an account or namespace is a different grant, managed by
[redshift_datashare_grant](https://registry.terraform.io/providers/netcheck-de/redshift/latest/docs/resources/datashare_grant).

## Example Usage

```terraform
resource "redshift_datashare_privilege" "share_admins" {
  database_name  = redshift_datashare.analytics.database
  datashare_name = redshift_datashare.analytics.name
  grantee_type   = "ROLE"
  grantee        = "share_admins"
  privileges     = ["ALTER", "SHARE"]
}
```

## Schema

### Required

- `database_name` (String) Local producer database that owns the datashare; grants run in it. Changing it replaces the grant.
- `datashare_name` (String) Outbound datashare receiving the permissions. Changing it replaces the grant.
- `grantee` (String) Receiving user, role, or group name; use `public` with `PUBLIC`. Changing it replaces the grant.
- `grantee_type` (String) `USER`, `ROLE`, `GROUP`, or `PUBLIC`. Changing it replaces the grant.
- `privileges` (Set of String) Exact explicit datashare permissions: `ALTER` adds or removes objects and sets `PUBLICACCESSIBLE`; `SHARE` grants consumers usage. Updated in place; an empty set revokes the owned permissions.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

Changing the database, datashare, or grantee replaces the grant; `privileges` is reconciled in place. Use
`grantee_type = "PUBLIC"` with `grantee = "public"` to grant to every user.

## Lifecycle and Ownership

Reads confirm that the outbound share exists in `database_name`
([SVV_DATASHARES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARES.html)) and that the grantee exists,
then read the explicit permissions from
[SVV_DATASHARE_PRIVILEGES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARE_PRIVILEGES.html). Extra
permissions are revoked before missing ones are granted, and the catalog is read again to verify the result. Statements
run in the producer database. A dropped share or grantee removes the resource from state. Deleting the resource revokes
only the permissions this grantee holds; other grantees are independent.

Grant options are not managed. `REVOKE ... ON DATASHARE` documents no `GRANT OPTION FOR` form that removes only the
option, so a permission held `WITH GRANT OPTION` is reported as an error instead of being silently downgraded. To bring
such a grantee under Terraform, revoke the permission itself outside Terraform (`REVOKE ALTER ON DATASHARE ... FROM
user`, which drops the option with it), then apply, which grants the permission again without the option. Superusers and users with `ACCESS SYSTEM TABLE` see every row of `SVV_DATASHARE_PRIVILEGES`;
other users see only identities they have access to or own, so the provider user needs that visibility.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_datashare_privilege.share_admins
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "admin"
    database_name  = "warehouse"
    datashare_name = "analytics"
    grantee        = "share_admins"
    grantee_type   = "ROLE"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_datashare_privilege.share_admins \
  '{"workgroup_name":"warehouse","database":"admin","database_name":"warehouse","datashare_name":"analytics","grantee":"share_admins","grantee_type":"ROLE"}'
```

The identity's `database` is the provider's administration database; `database_name` is the share's producer database.
