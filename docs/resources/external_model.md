# redshift_external_model (Resource)

Manages an Amazon Bedrock model created with `CREATE EXTERNAL MODEL` and the inference function Redshift creates for
it, which sends prompts to Amazon Bedrock from SQL. See AWS
[CREATE EXTERNAL MODEL](https://docs.aws.amazon.com/redshift/latest/dg/r_create_external_model.html),
[DROP MODEL](https://docs.aws.amazon.com/redshift/latest/dg/r_DROP_MODEL.html),
[SHOW MODEL](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_MODEL.html), and
[Amazon Redshift ML integration with Amazon Bedrock](https://docs.aws.amazon.com/redshift/latest/dg/machine-learning-br.html).

## SQL Statements

```sql
CREATE EXTERNAL MODEL schema.name FUNCTION function IAM_ROLE ... MODEL_TYPE BEDROCK SETTINGS (...);
DROP MODEL schema.name;
```

## Example Usage

```terraform
resource "redshift_external_model" "summarizer" {
  database      = "analytics"
  schema        = "ml"
  name          = "summarizer"
  function      = "f_summarize"
  iam_role      = aws_iam_role.redshift_bedrock.arn
  model_id      = "anthropic.claude-3-haiku-20240307-v1:0"
  prompt        = "Summarize the following support ticket in one sentence:"
  request_type  = "UNIFIED"
  response_type = "VARCHAR"
}

# Bedrock calls are granted on the model; its inference function cannot be granted directly.
resource "redshift_object_grant" "summarizer" {
  database_name = redshift_external_model.summarizer.database
  schema_name   = redshift_external_model.summarizer.schema
  object_name   = redshift_external_model.summarizer.name
  object_type   = "MODEL"
  grantee_type  = "ROLE"
  grantee       = "support_analysts"
  privileges    = ["EXECUTE"]
}
```

## Schema

### Required

- `database` (String) Local database containing the model.
- `function` (String) Name of the inference function the model creates in `schema`. The model owns the function: `DROP MODEL` drops it, `EXECUTE` is granted on the model, and `redshift_function` must not manage it.
- `iam_role` (String) `DEFAULT`, in any case, for the warehouse's default IAM role, or the ARN of an associated IAM role allowed to invoke the Amazon Bedrock model. Another case of `DEFAULT` is recorded in place.
- `model_id` (String) Amazon Bedrock model ID, such as `anthropic.claude-v2`.
- `name` (String) Model name, unique among the models of the schema.
- `schema` (String) Existing schema containing the model and its inference function.

### Optional

- `prompt` (String) Static prompt prefix added to the beginning of every request; only with `request_type = "UNIFIED"`.
- `request_type` (String) Request format: `UNIFIED` (the default) uses the Amazon Bedrock Converse API and an inference function taking the input text with optional settings; `RAW` passes one `SUPER` request in the model's own format. Accepted in any case; another case of the same keyword is recorded in place.
- `response_type` (String) Response format: `VARCHAR` (the default) returns the generated text, `SUPER` the whole response. `RAW` requests require `SUPER`. Accepted in any case; another case of the same keyword is recorded in place.
- `suffix` (String) Static prompt suffix added to the end of every request; only with `request_type = "UNIFIED"`.

### Read-Only

- `id` (String) JSON import identity within the configured warehouse; independent of connection method and Data API execution history.
- `owner` (String) SQL user owning the model, as `SHOW MODEL` reports it; null when it is not reported.

## Request and Response Formats

| `request_type`      | Inference function                                          | `response_type`                | `prompt`, `suffix` |
|---------------------|-------------------------------------------------------------|--------------------------------|--------------------|
| `UNIFIED` (default) | `function(input_text [, inference_config [, ...]])`         | `VARCHAR` (default) or `SUPER` | allowed            |
| `RAW`               | `function(request_super)` in the Bedrock model's own format | `SUPER`, which must be set     | not allowed        |

Planning rejects the combinations the table excludes. `MODEL_ID` is sent as a string literal, and `REQUEST_TYPE` and
`RESPONSE_TYPE` are always stated, so the statement records the formats the state holds.

## Lifecycle and Ownership

Creating a model requires a superuser, a user with the `CREATE MODEL` privilege, or a role granted `CREATE MODEL` with
[`redshift_system_grant`](https://registry.terraform.io/providers/netcheck-de/redshift/latest/docs/resources/system_grant).
The IAM role, its permission to invoke the Bedrock model, its association with the cluster or namespace, and access to
the model in Amazon Bedrock belong to the AWS provider and the Bedrock console.

The model owns its inference function: Redshift creates it in `schema` with the model and drops it with `DROP MODEL`.
Do not manage the function with `redshift_function`, and do not grant `EXECUTE` on it directly; grant `EXECUTE` on the
model with [`redshift_object_grant`](https://registry.terraform.io/providers/netcheck-de/redshift/latest/docs/resources/object_grant)
and `object_type = "MODEL"`. `DROP MODEL` commits immediately; the provider runs each statement on its own, outside a
transaction block.

`redshift_models` lists the models of a database, including trained models that this resource does not manage.

## Reconciliation

Refresh finds the model in `SHOW MODEL ALL` of its database and reads its settings from the `SHOW MODEL` key and value
rows; Redshift has no `ALTER MODEL`, so no change runs SQL in place, and every change replaces the model.

| Change                                                      | Result                                                                                                                          |
|-------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| `database`, `schema`, or `name`                             | replaces the model: the provider never moves or renames a model                                                                 |
| `function`                                                  | replaces the model: the inference function is created with the model                                                            |
| `iam_role` changed                                          | replaces the model, except when adopting an unread value after import                                                           |
| `iam_role` respelled as another case of `DEFAULT`           | no SQL; the state records the configured spelling                                                                               |
| `model_id`, `prompt`, or `suffix` set, changed, or removed  | replaces the model                                                                                                              |
| `request_type` or `response_type` changed                   | replaces the model, except when adopting an unread response type after import; omitted values default to `UNIFIED` or `VARCHAR` |
| `request_type` or `response_type` respelled in another case | no SQL; the state records the configured spelling                                                                               |

**Drift.** `SHOW MODEL` documents the owner and the function name, but not the keys of the Bedrock settings, so refresh
reads `function`, `iam_role`, `model_id`, `prompt`, `suffix`, `request_type`, and `response_type` only where
`SHOW MODEL` prints a matching key (such as `Function Name`, `IAM Role`, or `Model ID`), and otherwise keeps the
state. A reported value that differs from the state replaces the model in the next plan. A configured `DEFAULT` role
matches whichever role the catalog reports, and only the model's owner sees the IAM role. `owner` reports the catalog
owner. A dropped model or database is removed from state, and the next plan creates the model again.

## Import

Use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_external_model.summarizer
  id = jsonencode({
    database = "analytics"
    schema   = "ml"
    name     = "summarizer"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_external_model.summarizer \
  '{"database":"analytics","schema":"ml","name":"summarizer"}'
```

Import reads the settings `SHOW MODEL` reports. To the model's owner it prints the model ID, prompt, suffix, request
type, function, and IAM role (`DEFAULT` as `default-aws-iam-role`); other users see no role. It never prints the
response type, so import leaves it null until the first apply adopts configuration, including the `VARCHAR` default.
The first apply adopts the configured response type and an unreported IAM role without SQL or replacement. Import
cannot verify these values: configure the model's actual settings. Later changes replace the model normally.
