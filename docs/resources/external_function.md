# redshift_external_function (Resource)

Manages a scalar Lambda user-defined function (UDF) that Redshift runs by invoking an AWS Lambda function. See AWS
[CREATE EXTERNAL FUNCTION](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_EXTERNAL_FUNCTION.html),
[ALTER FUNCTION](https://docs.aws.amazon.com/redshift/latest/dg/r_ALTER_FUNCTION.html),
[DROP FUNCTION](https://docs.aws.amazon.com/redshift/latest/dg/r_DROP_FUNCTION.html), and
[Scalar Lambda UDFs](https://docs.aws.amazon.com/redshift/latest/dg/udf-creating-a-lambda-sql-udf.html).

```sql
CREATE EXTERNAL FUNCTION schema.name(arguments) RETURNS return_type ...;
CREATE OR REPLACE EXTERNAL FUNCTION schema.name(arguments) RETURNS return_type ...;
ALTER FUNCTION schema.name(arguments) OWNER TO owner;
DROP FUNCTION schema.name(arguments);
```

## Example Usage

```terraform
resource "redshift_external_function" "upper" {
  database        = redshift_database.warehouse.name
  schema          = "public"
  name            = "f_upper"
  arguments       = ["varchar"]
  return_type     = "varchar"
  volatility      = "STABLE"
  lambda_function = aws_lambda_function.upper.function_name
  iam_role        = aws_iam_role.lambda_invoker.arn
  retry_timeout   = 3000
  max_batch_rows  = 500
}
```

## Schema

### Required

- `arguments` (List of String) Input argument data types in order, at most 32, from the types Lambda UDFs support: `SMALLINT`, `INTEGER`, `BIGINT`, `DECIMAL`, `REAL`, `DOUBLE PRECISION`, `CHAR`, `VARCHAR`, `BOOLEAN`, `DATE`, `TIMESTAMP`, and their aliases. Use `[]` for a function without arguments. With `name` they identify the overload. Changing the canonical argument types replaces the function; a different spelling of the same types, such as `int` for `integer`, is recorded in place.
- `database` (String) Local database containing the function. Changing it replaces the function.
- `iam_role` (String) `default` for the warehouse's default IAM role, or the ARN of an associated IAM role allowed to invoke the Lambda function; chain roles with commas and no spaces. Applied in place with `CREATE OR REPLACE`. Redshift does not expose it in a documented catalog view, so changes made outside Terraform are not detected and import leaves it unset until the next apply restates the function.
- `lambda_function` (String) Name or ARN of the Lambda function Redshift invokes. Applied in place with `CREATE OR REPLACE`, which requires a superuser. Redshift does not expose it in a documented catalog view, so changes made outside Terraform are not detected and import leaves it unset until the next apply restates the function.
- `name` (String) Function name; AWS recommends the reserved `f_` prefix to avoid conflicts with built-in functions. Changing it replaces the function.
- `return_type` (String) Result data type, from the same types as `arguments`. Changing the base type replaces the function; a new length or precision is applied in place with `CREATE OR REPLACE`.
- `schema` (String) Schema containing the function. Changing it replaces the function.

### Optional

- `max_batch_rows` (Number) Maximum rows per Lambda invocation, from 1 to 2,147,483,647 (the default). Applied in place with `CREATE OR REPLACE`. Redshift does not expose it in a documented catalog view, so changes made outside Terraform are not detected and import leaves it unset until the next apply restates the function.
- `max_batch_size` (Number) Maximum payload per Lambda invocation in `max_batch_size_unit`, from 1 KB to 5 MB (the default). Applied in place with `CREATE OR REPLACE`. Redshift does not expose it in a documented catalog view, so changes made outside Terraform are not detected and import leaves it unset until the next apply restates the function.
- `max_batch_size_unit` (String) Unit of `max_batch_size`: `KB` or `MB`. Unset means KB, as in Redshift. Requires `max_batch_size`.
- `owner` (String) SQL user owning the function, applied with `ALTER FUNCTION ... OWNER TO`, which requires a superuser. Unset keeps the creating user and reports it.
- `retry_timeout` (Number) Total retry backoff in milliseconds; `0` disables retries. Unset uses the Redshift default of 20,000. Applied in place with `CREATE OR REPLACE`. Redshift does not expose it in a documented catalog view, so changes made outside Terraform are not detected and import leaves it unset until the next apply restates the function.
- `volatility` (String) `VOLATILE` (default) or `STABLE`; Redshift does not support `IMMUTABLE` for Lambda UDFs. Applied in place with `CREATE OR REPLACE`, which requires a superuser.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

## Lifecycle and Ownership

The Lambda function, its execution role, and the IAM role that lets the warehouse invoke it belong to the AWS
provider; associate that role with the cluster or namespace, or use `iam_role = "default"`. Creating the function
requires superuser or the `CREATE [ OR REPLACE ] EXTERNAL FUNCTION` privilege and `USAGE ON LANGUAGE exfunc`.

`name` and the canonical `arguments` identify the overload. Changing them, the database, the schema, or the base
type of `return_type` replaces the function. Every other definition option changes in place with
`CREATE OR REPLACE EXTERNAL FUNCTION`, which redefines the existing overload instead of dropping it but requires a
superuser. `owner`
changes with `ALTER FUNCTION ... OWNER TO`, which also requires a superuser.

Redshift reports the signature, result type, volatility, language, and owner in `pg_proc`, which refresh reads. No
documented catalog view reports `lambda_function`, `iam_role`, or the retry and batch options, so Terraform keeps them
from configuration: changes made outside Terraform are not detected, and an import leaves them unset until the next
apply restates the definition. `DROP FUNCTION` does **not** cascade; remove dependent views first.

For the same reason there is no `redshift_external_function` data source: a lookup could not report the Lambda
options. `redshift_functions` lists Lambda UDFs with their signature, return type, volatility, language, and owner,
and `redshift_routine_parameters` lists their parameters.

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity. `arguments` is the canonical signature
Create records: the argument types as the catalog spells them, without length or precision, separated by `", "`, and
`""` for a function without arguments.

```terraform
import {
  to = redshift_external_function.upper
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "warehouse"
    schema         = "public"
    name           = "f_upper"
    arguments      = "character varying"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_external_function.upper \
  '{"workgroup_name":"warehouse","database":"warehouse","schema":"public","name":"f_upper","arguments":"character varying"}'
```
