# redshift_table_security (Resource)

Turns row-level security (RLS) on or off for one existing table, view, late-binding view, or materialized view, and
sets how several policies combine and whether RLS also applies to datashare consumers. See AWS
[ALTER TABLE](https://docs.aws.amazon.com/redshift/latest/dg/r_ALTER_TABLE.html) and
[SVV_RLS_RELATION](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_RLS_RELATION.html).

## SQL Statements

```sql
ALTER TABLE schema.relation ROW LEVEL SECURITY ON ...;
ALTER TABLE schema.relation ROW LEVEL SECURITY OFF ...;
```

~> **Destroying this resource turns row-level security OFF.** Every policy attached to the relation stops filtering,
and all rows become visible to anyone with `SELECT` on it. To keep a relation protected while it leaves Terraform,
remove the resource from state with a `removed` block instead of destroying it.

## Example Usage

```terraform
# Attach the policies first, so readers are never left without a policy once RLS is on.
resource "redshift_table_security" "orders" {
  database           = "analytics"
  schema             = "sales"
  relation           = "orders"
  row_level_security = true
  conjunction_type   = "AND"

  depends_on = [redshift_rls_policy_attachment.analysts]
}
```

## Schema

### Required

- `database` (String) Local database containing the relation. Changing it replaces the table security.
- `relation` (String) Table, view, late-binding view, or materialized view; the resource never creates or drops it. Changing it replaces the table security.
- `row_level_security` (Boolean) Whether row-level security is on. While it is on, users see only the rows an attached policy permits, and no rows when no policy applies to them; superusers and `sys:secadmin` holders are exempt.
- `schema` (String) Schema of the relation. Changing it replaces the table security.

### Optional

- `conjunction_type` (String) `AND` or `OR`: how several policies attached for the same user combine (`CONJUNCTION TYPE`). Redshift defaults to `AND`; unset keeps the current value.
- `datashare_row_level_security` (Boolean) Row-level security for datashare consumers (`ROW LEVEL SECURITY { ON | OFF } FOR DATASHARES`). While it is on, which is the default, consumer queries of the RLS-protected relation fail; `false` makes the relation readable through datashares **without any row filtering on the consumer side**. Unset keeps the current value.

### Read-Only

- `id` (String) JSON import identity; independent of Data API execution history.

## Lifecycle and Ownership

Only superusers and `sys:secadmin` holders can change these settings. While RLS is on, a user sees only the rows that an
attached policy permits and no rows at all when no policy applies to them, so attach the policies before turning RLS on.
`ROW LEVEL SECURITY OFF FOR DATASHARES` makes the relation readable over datashares without row filtering on the
consumer side, while the producer keeps RLS.

The resource never creates or drops the relation. Deletion only turns RLS off; the conjunction type and datashare
setting stay as they are.

## Reconciliation

Refresh reads the settings from `svv_rls_relation`; an update runs one `ALTER TABLE ... ROW LEVEL SECURITY` statement
for the switch and conjunction type and one for the datashare setting, as far as they changed, and re-reads the catalog
to verify the result; a changed `database`, `schema`, or `relation` replaces the table security.

| Change                                 | Result                                                                                                                                                                     |
|----------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `database`, `schema`, or `relation`    | replaces the table security: destroying it turns RLS off on the old relation, and creating it applies the configured settings to the new one                               |
| `row_level_security`                   | `ALTER TABLE ... ROW LEVEL SECURITY ON` or `OFF`, followed by `CONJUNCTION TYPE` with the planned conjunction type, so the conjunction type never changes as a side effect |
| `conjunction_type` changed             | `ALTER TABLE ... ROW LEVEL SECURITY ON` or `OFF ... CONJUNCTION TYPE` with the planned switch; together with a `row_level_security` change, one statement covers both      |
| `conjunction_type` removed             | no SQL; the relation keeps its conjunction type, which is still reported                                                                                                   |
| `datashare_row_level_security` changed | `ALTER TABLE ... ROW LEVEL SECURITY ON FOR DATASHARES` or `OFF FOR DATASHARES`, after the switch                                                                           |
| `datashare_row_level_security` removed | no SQL; the relation keeps its datashare setting, which is still reported                                                                                                  |

**Drift.** Refresh compares `svv_rls_relation` with the state. A relation that view does not list has never been
protected and reports RLS off, `AND`, and RLS on for datashares. A `row_level_security`, or a configured
`conjunction_type` or `datashare_row_level_security`, changed outside Terraform is set back with the statements above;
an omitted `conjunction_type` or `datashare_row_level_security` follows the catalog and never plans a change. A dropped
relation or database removes the resource from state. Policies and their attachments are never read; manage them with
`redshift_rls_policy` and `redshift_rls_policy_attachment`.

The following examples change the relation `public.events` with RLS on, `AND`, and RLS on for datashares, and show the
statements the update runs:

```terraform
conjunction_type = "OR" # was "AND"
```

```sql
ALTER TABLE "public"."events" ROW LEVEL SECURITY ON CONJUNCTION TYPE OR;
```

```terraform
row_level_security = false # was true
```

```sql
ALTER TABLE "public"."events" ROW LEVEL SECURITY OFF CONJUNCTION TYPE AND;
```

```terraform
datashare_row_level_security = false # was true
```

```sql
ALTER TABLE "public"."events" ROW LEVEL SECURITY OFF FOR DATASHARES;
```

## Import

In Terraform 1.5 and later, use an `import` block with a JSON identity:

```terraform
import {
  to = redshift_table_security.orders
  id = jsonencode({
    workgroup_name = "warehouse"
    database       = "analytics"
    schema         = "sales"
    relation       = "orders"
  })
}
```

Alternatively, use `terraform import`:

```shell
terraform import redshift_table_security.orders \
  '{"workgroup_name":"warehouse","database":"analytics","schema":"sales","relation":"orders"}'
```
