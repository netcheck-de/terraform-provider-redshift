# redshift_columns (Data Source)

Lists the columns of one database's tables, views, and external tables. See AWS
[SVV_ALL_COLUMNS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_ALL_COLUMNS.html).

```sql
SELECT ... FROM svv_all_columns WHERE database_name = '...' AND schema_name = '...' AND table_name = '...';
```

## Example Usage

```terraform
data "redshift_columns" "daily_summary" {
  database = "analytics"
  schema   = "reporting"
  table    = "daily_summary"
}

output "required_columns" {
  value = [for column in data.redshift_columns.daily_summary.items : column.name if column.nullable == false]
}
```

## Schema

### Optional

- `database` (String) Database whose columns are listed; defaults to the provider's `database`.
- `schema` (String) Only columns of relations in this schema.
- `table` (String) Only columns of relations with this name.

### Read-Only

- `id` (String) JSON identity of this listing: the warehouse binding, the database, and the configured filters.
- `items` (Attributes List) Matching objects; empty when nothing matches. (see [below for nested schema](#nestedatt--items))

<a id="nestedatt--items"></a>
### Nested Schema for `items`

Read-Only:

- `character_maximum_length` (Number) Maximum length of a character column; null for other types.
- `data_type` (String) Data type name as the catalog reports it, such as `integer` or `character varying`, without length or precision.
- `database` (String) Database containing the relation.
- `default` (String) Default expression; null when the column has none.
- `name` (String) Column name.
- `nullable` (Boolean) Whether the column accepts NULL; null when the catalog has no information.
- `numeric_precision` (Number) Numeric precision as the catalog reports it: decimal digits for `DECIMAL`/`NUMERIC`, bits for integer types (for example 32 for `INTEGER` and 16 for `SMALLINT`); null for non-numeric types.
- `numeric_scale` (Number) Numeric scale as the catalog reports it: digits after the decimal point for `DECIMAL`/`NUMERIC`, 0 for integer types; null for non-numeric types.
- `ordinal_position` (Number) Position of the column in the relation, starting at 1.
- `remarks` (String) Comment on the column; null when it has none.
- `schema` (String) Schema containing the relation.
- `table` (String) Relation containing the column.
<!-- markdownlint-enable MD013 MD022 MD033 -->

`database` defaults to the provider's `database`; the read runs in the provider's database. `id` combines the
warehouse binding, the listed database, and the configured filters. Items are ordered by schema, table, and
`ordinal_position`; no match returns an empty `items` list. Without a `table` filter, the listing covers every
relation of the database, so filter as narrowly as possible on large warehouses.

`data_type` is the bare type name; length, precision, and scale are separate attributes. `nullable` is null when the
catalog has no nullability information, for example for some external columns. An empty `column_default` or remarks
value cannot be told apart from none and is reported as null. Superusers see every column; other users see only
columns of relations they own.
