# redshift_datashare_tables (Data Source)

Lists the tables, views, late-binding views, and materialized views of the outbound datashares in one producer
database, as `redshift_datashare_table` manages them. See AWS
[SVV_DATASHARE_OBJECTS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARE_OBJECTS.html).

## Example Usage

```terraform
data "redshift_datashare_tables" "reporting" {
  database  = "analytics"
  datashare = "reporting"
  schema    = "public"
}

output "shared_tables" {
  value = data.redshift_datashare_tables.reporting.datashare_tables[*].table
}
```

## Read Behavior

`datashare_tables` is empty when nothing matches; it is ordered by share and qualified name. Omit `database` to use the
provider database, `datashare` to list every outbound share of that database, and `schema` to list every schema. Only
datashares of that one database are listed; `redshift_datashares` lists the datashares of every database. A database
that does not exist or is not local, such as a datashare consumer database, lists nothing.

The listing observes current membership, not the statements that established it: it includes relations added
explicitly, by `ADD ALL TABLES IN SCHEMA`, by scoped grants, or by `INCLUDENEW`, which the catalog does not distinguish.
The catalog reports each relation as an unquoted `schema.table` name. The longest schema of the same share that prefixes
it becomes `schema`, so a schema name containing a period still resolves; a relation whose schema is not a share member
is split at its first period.

`id` (String, computed) is the listing's provider-relative JSON identity containing the database and configured filters.

Superusers see the members of every share; other users see only the rows `SVV_DATASHARE_OBJECTS` and `SVV_DATASHARES`
show them. Only read-only SQL is executed.
