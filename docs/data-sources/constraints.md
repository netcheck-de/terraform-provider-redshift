# redshift_constraints (Data Source)

Lists the key constraints of one database's tables. Redshift does not enforce them, but the query planner relies on
them. See AWS [Defining table constraints](https://docs.aws.amazon.com/redshift/latest/dg/t_Defining_constraints.html)
and [Querying the catalog tables](https://docs.aws.amazon.com/redshift/latest/dg/c_join_PG.html).

```sql
SELECT ... FROM pg_constraint WHERE contype IN ('p', 'u', 'f') ...;
```

## Example Usage

```terraform
data "redshift_constraints" "orders_keys" {
  database        = "analytics"
  schema          = "reporting"
  table           = "orders"
  constraint_type = "PRIMARY KEY"
}

resource "redshift_comment" "orders_key" {
  for_each = { for key in data.redshift_constraints.orders_keys.items : key.name => key }

  database_name   = each.value.database
  object_type     = "CONSTRAINT"
  schema_name     = each.value.schema
  object_name     = each.value.table
  constraint_name = each.value.name
  text            = "Business key: ${join(", ", each.value.columns)}."
}
```

## Schema

### Optional

- `constraint_type` (String) Only constraints of this type: `PRIMARY KEY`, `UNIQUE`, or `FOREIGN KEY`.
- `database` (String) Database whose constraints are listed; defaults to the provider's `database`.
- `schema` (String) Only constraints of tables in this schema.
- `table` (String) Only constraints of tables with this name.

### Read-Only

- `id` (String) JSON identity of this listing: the warehouse binding, the database, and the configured filters.
- `items` (Attributes List) Matching objects; empty when nothing matches. (see [below for nested schema](#nestedatt--items))

### Nested Schema for `items`

Read-Only:

- `columns` (List of String) Constrained columns in key order.
- `constraint_type` (String) `PRIMARY KEY`, `UNIQUE`, or `FOREIGN KEY`.
- `database` (String) Database containing the table.
- `definition` (String) Constraint definition as `pg_get_constraintdef` renders it, such as `PRIMARY KEY (id)`.
- `name` (String) Constraint name, as used by `redshift_comment` with `object_type = "CONSTRAINT"`.
- `referenced_columns` (List of String) Referenced columns of a foreign key, paired with `columns` by position; null for other constraints.
- `referenced_schema` (String) Schema of the table a foreign key references; null for other constraints.
- `referenced_table` (String) Table a foreign key references; null for other constraints.
- `schema` (String) Schema containing the table.
- `table` (String) Table the constraint belongs to.
<!-- markdownlint-enable MD013 MD022 MD033 -->

`database` defaults to the provider's `database`. `PG_CONSTRAINT` only covers the database a statement runs in, so
the read connects to the listed database, which must be a local database. `id` combines the warehouse binding, the
listed database, and the configured filters. Items are ordered by schema, table, and constraint name; no match returns
an empty `items` list.

Key columns are parsed from `pg_get_constraintdef`, because the catalog's column-number arrays are not readable
through the provider's SQL transports; `columns` and `referenced_columns` keep key order, so the n-th columns of a composite foreign key
correspond. Use `name` with `redshift_comment` and `object_type = "CONSTRAINT"` to annotate a constraint.
