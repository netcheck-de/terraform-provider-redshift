# redshift_external_tables (Data Source)

Lists the external tables of one database with their definitions, the tables `redshift_external_table` manages. See AWS
[SVV_EXTERNAL_TABLES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_EXTERNAL_TABLES.html) and
[SVV_EXTERNAL_COLUMNS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_EXTERNAL_COLUMNS.html).

## Example Usage

```terraform
data "redshift_external_tables" "raw" {
  database = "warehouse"
  schema   = "raw"
}

output "external_table_locations" {
  value = { for table in data.redshift_external_tables.raw.external_tables : table.name => table.location }
}
```

## SQL Statements

```sql
-- Check that the selected database is local.
SELECT ... FROM svv_redshift_databases WHERE database_name = '...' AND database_type = 'local';

SELECT ... FROM svv_external_tables WHERE redshift_database_name = '...' AND schemaname = '...';

```

## Read Behavior

`database` defaults to the provider's `database`. The `schema` filter compares without case, as Redshift folds
identifiers. Items are ordered by schema and name; no match returns an empty `external_tables` list, and the column read
is skipped. `id` combines the listed database and configured filters within the warehouse.

Each item reports what the `redshift_external_table` lookup reports: `column` in catalog order with Redshift type names
(types Redshift cannot declare, such as Glue's `string`, in UPPERCASE), every catalog table property, `stored_as` null
when the input format class belongs to no named format, and `serde` null when it is the format's default SerDe. A table
whose columns the catalog does not report is an error. A database that is not local lists no tables. Superusers see
every table; other users see only the tables they have access to.
