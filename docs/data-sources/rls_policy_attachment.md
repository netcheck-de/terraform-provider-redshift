# redshift_rls_policy_attachment (Data Source)

Checks whether one policy is attached to one relation for one user, role, or `PUBLIC`. See AWS
[SVV_RLS_ATTACHED_POLICY](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_RLS_ATTACHED_POLICY.html).

## Catalog Query

```sql
SELECT ... FROM svv_rls_attached_policy WHERE polname = 'policy' AND relname = 'relation' ...;
```

## Example Usage

```terraform
data "redshift_rls_policy_attachment" "analysts" {
  policy       = "own_region"
  database     = "analytics"
  schema       = "sales"
  relation     = "orders"
  grantee      = "analysts"
  grantee_type = "ROLE"
}
```

## Schema

### Required

- `database` (String) Local database containing both the policy and the relation.
- `grantee` (String) User or role name the policy applies to; use `public` with `grantee_type = "PUBLIC"`. Policies attached to superusers or `sys:secadmin` holders are ignored.
- `grantee_type` (String) `USER`, `ROLE`, or `PUBLIC`.
- `policy` (String) RLS policy to attach.
- `relation` (String) Table, view, late-binding view, or materialized view the policy filters; it must have every `WITH` column of the policy.
- `schema` (String) Schema of the relation.

### Read-Only

- `exists` (Boolean) Whether this explicit relationship exists. False also covers missing parents.
- `id` (String) JSON identity of the observed object, using the same format as the paired resource. Null for a missing relationship.

`id` (String, computed) is the attachment's JSON identity, using the same keys as the paired resource. It is null when
