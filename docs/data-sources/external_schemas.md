# redshift_external_schemas (Data Source)

Lists the external schemas of one local database with their source form, recorded options, and owner, in the shape of
`redshift_external_schema`. See AWS
[SVV_EXTERNAL_SCHEMAS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_EXTERNAL_SCHEMAS.html).

## Example Usage

```terraform
data "redshift_external_schemas" "analytics" {
  database = "analytics"
}

output "glue_databases" {
  value = {
    for schema in data.redshift_external_schemas.analytics.external_schemas :
    schema.name => schema.glue_database if schema.source_type == "DATA_CATALOG"
  }
}
```

## Read Behavior

`database` defaults to the provider's `database`, and the read runs in that database with one query. `id` combines the
listed database within the warehouse. Items are ordered by name; a database without visible external schemas returns
an empty `external_schemas` list.

Each item is decoded as `redshift_external_schema` reads it: `source_type` follows from the catalog's schema kind, and
options that the catalog does not record in `esoptions` are null. Schemas of kinds the resource cannot manage, such as
system-table schemas, are omitted. An incomplete catalog entry, such as a `DATA_CATALOG` schema without an IAM role or
undecodable options, is an error.

`SVV_EXTERNAL_SCHEMAS` shows a regular user only their own external schemas, so only a superuser connection lists
every external schema of the database.
