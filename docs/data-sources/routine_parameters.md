# redshift_routine_parameters (Data Source)

Lists the parameters of user-defined functions and stored procedures in one database, one item per parameter and
overload, without managing them. See AWS
[SHOW PARAMETERS](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_PARAMETERS.html) and
[PG_PROC_INFO](https://docs.aws.amazon.com/redshift/latest/dg/r_PG_PROC_INFO.html).

## Catalog Query

```sql
SELECT ... FROM pg_proc_info WHERE prokind IN ('f', 'p') AND nspname = '...' AND proname = '...';
SHOW PARAMETERS OF { FUNCTION | PROCEDURE } database.schema.routine_name(arguments);
```

## Example Usage

```terraform
data "redshift_routine_parameters" "upper" {
  database     = "warehouse"
  schema       = "public"
  routine_name = "f_upper"
  routine_type = "FUNCTION"
}

output "upper_inputs" {
  value = [for parameter in data.redshift_routine_parameters.upper.routine_parameters : parameter.data_type if parameter.mode == "IN"]
}
```

## Schema

### Optional

- `database` (String) Database to list routines from; defaults to the provider database.
- `routine_name` (String) Only routines with this exact name, including every overload.
- `routine_type` (String) Only routines of this type: `FUNCTION` or `PROCEDURE`.
- `schema` (String) Only routines in this schema.

### Read-Only

- `id` (String) JSON identity of this listing: the warehouse binding, the database, and the configured filters.
- `routine_parameters` (Attributes List) Matching objects; empty when nothing matches. (see [below for nested schema](#nestedatt--routine_parameters))

### Nested Schema for `routine_parameters`

Read-Only:

- `arguments` (List of String) Input argument types that identify the routine's overload, as the catalog reports them but in uppercase, such as `INTEGER`.
- `data_type` (String) Parameter data type, as `SHOW PARAMETERS` reports it but in uppercase, such as `CHARACTER VARYING`.
- `database` (String) Database containing the routine.
- `mode` (String) `IN`, `OUT`, `INOUT`, or `RETURN` for a function's result.
- `ordinal_position` (Number) Position of the parameter, starting at 1; `0` for a function's `RETURN` row.
- `parameter_name` (String) Parameter name; empty for unnamed parameters and the `RETURN` row.
- `routine_name` (String) Name of the function or procedure.
- `routine_type` (String) `FUNCTION` or `PROCEDURE`.
- `schema` (String) Schema containing the routine.
<!-- markdownlint-enable MD013 MD022 MD033 -->

The listing first finds the matching overloads in `pg_proc_info` and then runs `SHOW PARAMETERS` once per overload, so
narrow it with `schema` and `routine_name`. Functions add a `RETURN` row at position `0` for their result. Viewing a
routine requires superuser, ownership, or `USAGE` on its schema and `EXECUTE` on the routine.
