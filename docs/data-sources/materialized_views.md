# redshift_materialized_views (Data Source)

Lists the materialized views of one database with their definitions, refresh settings, and owners, the views
`redshift_materialized_view` manages. See AWS
[SVV_MV_INFO](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_MV_INFO.html).

## Example Usage

```terraform
data "redshift_materialized_views" "reporting" {
  database = "analytics"
  schema   = "reporting"
}

output "manually_refreshed_views" {
  value = [for view in data.redshift_materialized_views.reporting.materialized_views : "${view.schema}.${view.name}" if view.auto_refresh == false]
}
```

## SQL Statements

Simplified SQL used by the provider to read this data source.

```sql
-- Check that the selected database is local.
SELECT ... FROM svv_redshift_databases WHERE database_name = '...' AND database_type = 'local';

-- List the views and materialized views of the selected database.
SELECT ... FROM pg_views WHERE schemaname = '...';

-- Read the automatic refresh settings of the selected database's materialized views.
SELECT ... FROM svv_mv_info WHERE database_name = '...' AND schema_name = '...';
```

## Read Behavior

`database` defaults to the provider's `database`. `pg_views` and `SVV_MV_INFO` cover only the connected database, so
both reads run in the listed database; the `SVV_MV_INFO` read is skipped when no materialized view matched. Items are
ordered by schema and name; no match returns an empty `materialized_views` list. `id` combines the listed database and
configured filters within the warehouse.

`pg_views` decides which materialized views exist, and each item reports what the `redshift_materialized_view` lookup
reports. `SVV_MV_INFO` shows a provider identity that is not a superuser only the materialized views it owns, so
`auto_refresh` is null for materialized views owned by other users. Ordinary and late-binding views are left out;
`redshift_views` lists them. A database that does not exist or is not local, such as a datashare consumer database,
lists nothing. Storage options have no catalog source every user can read; use the `redshift_materialized_view` lookup,
which reports them as null too.
