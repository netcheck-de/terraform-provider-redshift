# redshift_datashare_grants (Data Source)

Lists the consumer AWS accounts and Redshift namespaces granted `USAGE` on the outbound datashares of the provider's
namespace, as `redshift_datashare_grant` manages them. See AWS
[SVV_DATASHARE_CONSUMERS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARE_CONSUMERS.html).

## Example Usage

```terraform
data "redshift_datashare_grants" "reporting" {
  datashare = "reporting"
}

output "consumer_namespaces" {
  value = compact(data.redshift_datashare_grants.reporting.datashare_grants[*].namespace_id)
}
```


## Read Behavior

`datashare_grants` is empty when nothing matches; it is ordered by share, account, and namespace. One query in the
provider database covers the shares of every producer database, each reported with its `database`. A namespace grant
reports `namespace_id` with a null `account_id`; an account grant reports `account_id` with a null `namespace_id`.

`SVV_DATASHARE_CONSUMERS` reports an account granted usage `VIA DATA CATALOG` like a plain account grant, so the listing
does not report the grant form. Grants apply to SQL usage only; AWS authorization and association are separate.

`id` (String, computed) is the listing's provider-relative JSON identity containing the configured filters.

Superusers, share owners, and users with `ALTER` or `USAGE` on a share see its consumers; other users see none. Only
read-only SQL is executed.
