# redshift_datashare_privilege (Data Source)

Reads the explicit `ALTER` and `SHARE` permissions that one user, role, group, or `PUBLIC` holds on a producer datashare.
See AWS [GRANT](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html#grant-datashare-syntax).

```sql
SELECT ... FROM svv_datashare_privileges WHERE datashare_name = 'datashare_name' ...;
```

## Example Usage

```terraform
data "redshift_datashare_privilege" "share_admins" {
  database_name  = "warehouse"
  datashare_name = "analytics"
  grantee_type   = "ROLE"
  grantee        = "share_admins"
}
```

## Schema

### Required

- `database_name` (String) Local producer database that owns the datashare; grants run in it.
- `datashare_name` (String) Outbound datashare receiving the permissions.
- `grantee` (String) Receiving user, role, or group name; use `public` with `PUBLIC`.
- `grantee_type` (String) `USER`, `ROLE`, `GROUP`, or `PUBLIC`.

### Read-Only

- `id` (String) JSON identity of the observed object, using the same format as the paired resource. Null for a missing relationship.
- `privileges` (Set of String) Current explicit privileges for the selected tuple; inherited privileges are excluded.
<!-- markdownlint-enable MD013 MD022 MD033 -->

`id` (String, computed) is the permission tuple's JSON identity, using the same warehouse, provider database, producer
database, datashare, and grantee keys as the paired resource. A share and grantee without explicit permissions still
have an ID.

`privileges` is empty when the grantee holds no explicit datashare permissions. A missing share or grantee raises an
error. Permissions held with grant option are reported like any other, because the lookup only observes; no
permissions change.

Reads [SVV_DATASHARE_PRIVILEGES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARE_PRIVILEGES.html) after
checking [SVV_DATASHARES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARES.html) for the share.
