# redshift_debug_grants (Data Source)

Lists the `DEBUG` grants on one database of a warehouse with federated permissions, one element per grantee, without
taking ownership. Each element matches the identity of one `redshift_debug_grant`. See AWS
[SHOW GRANTS](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_GRANTS.html).

## Example Usage

```terraform
data "redshift_debug_grants" "sales" {
  database = "sales_db"
}

output "debug_grantees" {
  value = [for grant in data.redshift_debug_grants.sales.debug_grants : "${grant.grantee_type} ${grant.grantee}"]
}
```

## SQL Statements

```sql
-- List the grants on the database, including its DEBUG grants.
SHOW GRANTS ON DATABASE ...;
```

## Read Behavior

The statement names the database and runs in the provider database. Elements are the `DEBUG` rows: `global_user`
rows are listed as `USER`, `global_group` rows as `ROLE`, and `admins_of_account` rows as `ACCOUNT`. Remote
`database@catalog` aliases are rejected, because `SHOW GRANTS ON` can silently omit their grants; read those with the
[`redshift_debug_grant`](debug_grant.md) lookup.

`SHOW GRANTS` reports only grants visible to the provider's identity. `id` is the listing's provider-relative JSON
identity: the target `database` and the configured filters.
