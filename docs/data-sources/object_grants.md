# redshift_object_grants (Data Source)

Lists the explicit object grants `SHOW GRANTS` reports, one element per object and grantee, without taking ownership:
either every grant on one database, schema, table (including views), or template, or every object grant of one user
or role in one database. Each element matches the identity and privileges of one `redshift_object_grant`. See AWS
[SHOW GRANTS](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_GRANTS.html).

## Example Usage

```terraform
# Every grant on one table, including group and PUBLIC grantees.
data "redshift_object_grants" "events" {
  database_name = "analytics"
  object_type   = "TABLE"
  schema_name   = "reporting"
  object_name   = "events"
}

# Every object grant one role holds in one database, narrowed to one schema.
data "redshift_object_grants" "analysts" {
  database_name = "analytics"
  grantee       = "analysts"
  grantee_type  = "ROLE"
  schema_name   = "reporting"
}

output "events_grants" {
  value = { for grant in data.redshift_object_grants.events.object_grants : "${grant.grantee_type} ${grant.grantee}" => grant.privileges }
}
```

## Schema

### Optional

- `database_name` (String) Database whose grants are listed; defaults to the provider's `database`.
- `grantee` (String) Only grants to this identity name; `public` for `PUBLIC`.
- `grantee_type` (String) Only grants to `USER`, `ROLE`, `GROUP`, or `PUBLIC` identities.
- `object_name` (String) Table, view, or template whose grants are listed with `object_type`; otherwise only grants on objects of this name.
- `object_type` (String) `DATABASE`, `SCHEMA`, `TABLE` (including views), or `TEMPLATE` lists `SHOW GRANTS ON` that object, named by `database_name`, `schema_name`, and `object_name`. Omit it to list `SHOW GRANTS FOR` the `USER` or `ROLE` named by `grantee` and `grantee_type`. One of the two forms is required.
- `schema_name` (String) Only grants on objects in this schema.

### Read-Only

- `id` (String) JSON identity of this listing within the configured warehouse: its database scope and configured filters.
- `object_grants` (Attributes List) Matching objects; empty when nothing matches. (see [below for nested schema](#nestedatt--object_grants))

Read-Only:

## SQL Statements

Simplified SQL used by the provider to read this data source.

```sql
-- Read whether the database is local or shared, which selects the connection.
SELECT database_type FROM svv_redshift_databases WHERE database_name = '...';

-- List grants on the selected object.
SHOW GRANTS ON { DATABASE | SCHEMA | TABLE | TEMPLATE } ...;

-- List a user's or role's grants in the database.
SHOW GRANTS FOR [ROLE] ... FROM DATABASE ...;
```

## Read Behavior

Set `object_type` to list the grants on that object; `grantee` and `grantee_type` then narrow the elements, which also
covers groups and `PUBLIC`. Without `object_type`, `grantee` and `grantee_type` (`USER` or `ROLE`) select
`SHOW GRANTS FOR`; `schema_name` and `object_name` then narrow the elements. Other combinations are errors. Local
databases are read in their own database and shared (datashare consumer) databases from the provider database, as
`redshift_object_grant` reads them; a database that does not exist lists nothing.

Elements cover the `DATABASE`, `SCHEMA`, `TABLE`, and `TEMPLATE` grants of users, roles, groups, and `PUBLIC`.
Scoped grants, whose privilege scope is an object class such as `TABLES`, are listed by
[`redshift_grants`](grants.md). Routine and model grants need a signature or another catalog and are not listed;
read them with the [`redshift_object_grant`](object_grant.md) lookup. `grant_option_privileges` is null for
`SHOW GRANTS FOR`, which does not report grant options.

`SHOW GRANTS` documents no column that separates grants inherited through roles from explicit ones, so the listing
exposes none. Superusers see every grant; other users see only the grants `SHOW GRANTS` shows them. `SHOW GRANTS` fails
when more than 10,000 rows match. `id` is the listing's provider-relative JSON identity: the target `database_name` and
the configured filters.
