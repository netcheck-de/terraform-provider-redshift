# redshift_views (Data Source)

Lists the ordinary and late-binding views of one database with their definitions and owners, the views `redshift_view`
manages. See AWS [CREATE VIEW](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_VIEW.html).

## Example Usage

```terraform
data "redshift_views" "reporting" {
  database = "analytics"
  schema   = "reporting"
}

output "late_binding_views" {
  value = [for view in data.redshift_views.reporting.views : "${view.schema}.${view.name}" if view.late_binding]
}
```

## Read Behavior

`database` defaults to the provider's `database`. `pg_views` covers only the connected database, so the listing reads it
in the listed database. Items are ordered by schema and name; no match returns an empty `views` list. `id` combines the
listed database and configured filters within the warehouse.

Each item reports what `redshift_view` reports: `query` is the catalog's rendering of the definition, the `SELECT` of an
ordinary view and the complete `CREATE VIEW ... WITH NO SCHEMA BINDING` statement of a late-binding view. Materialized
views, which `pg_views` also lists, are left out; `redshift_materialized_views` lists them. Views in schemas starting
with `pg_` and in `information_schema` are system views and are left out. A database that is not local lists no views.
