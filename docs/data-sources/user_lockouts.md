# redshift_user_lockouts (Data Source)

Lists which password users are locked, whether each lockout was automatic or manual, and their recent failed logins,
without unlocking anyone. See AWS
[SHOW USER LOCKOUT](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_USER_LOCKOUT.html) and
[max_failed_login_attempts](https://docs.aws.amazon.com/redshift/latest/dg/max_failed_login_attempts.html).

## Catalog Query

```sql
SHOW USER LOCKOUT;
```

## Example Usage

```terraform
data "redshift_user_lockouts" "all" {}

data "redshift_user_lockouts" "reader" {
  user_name = "report_reader"
}

output "locked_users" {
  value = [for user in data.redshift_user_lockouts.all.user_lockouts : user.user_name if user.is_locked]
}
```

### Nested Schema for `user_lockouts`

Read-Only:

- `failed_login_attempts` (Number) Number of consecutive failed logins.
- `is_locked` (Boolean) Whether the user is currently locked.
- `last_failed_at` (String) Time of the most recent failed login, as Redshift reports it; null when not reported.
- `lock_reason` (String) `automatic` after reaching the failed-login threshold, `manual` after `ALTER USER ... NOLOGIN`; null when the user is not locked.
- `locked_at` (String) Time the user was locked, as Redshift reports it; null when not reported.
- `locked_by` (Number) User ID of the superuser who locked the user; null for an automatic lockout.
- `user_name` (String) Database user name.
<!-- markdownlint-enable MD013 MD022 MD033 -->

`SHOW USER LOCKOUT` requires a superuser, so the read fails for any other provider identity. Federated users are not
listed. The command has no filter, so `user_name` keeps the exact name after reading every row; `user_lockouts` is
ordered by user name and is empty when nothing matches. `locked_at` and `last_failed_at` are the timestamps as Redshift
reports them, and they, `lock_reason`, and `locked_by` are null when not reported.

Reading never changes a lockout or a counter; unlocking a user, which takes a superuser or the `ALTER USER` privilege,
stays outside this data source. The lockout threshold is the cluster-wide `max_failed_login_attempts` parameter, which
`redshift_configuration` reads. `id` (String, computed) is the listing's JSON identity: the warehouse binding, the
provider database, and the configured filter.
