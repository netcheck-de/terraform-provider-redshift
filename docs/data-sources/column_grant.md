# redshift_column_grant (Data Source)

Reads which columns of one table or view hold `SELECT` and `UPDATE` for one grantee. See AWS
[SVV_COLUMN_PRIVILEGES](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_COLUMN_PRIVILEGES.html).

## Catalog Query

```sql
SELECT ... FROM svv_column_privileges WHERE namespace_name = '...' AND relation_name = '...' AND identity_name = '...';
```

## Example Usage

```terraform
data "redshift_column_grant" "events" {
  database_name = "analytics"
  schema_name   = "reporting"
  object_name   = "events"
  grantee       = "analysts"
  grantee_type  = "ROLE"
}
```

## Schema

### Required

- `database_name` (String) Local database containing the table or view.
- `grantee` (String) Receiving identity name; use `public` for `PUBLIC`.
- `grantee_type` (String) `ROLE`, `USER`, `GROUP`, or `PUBLIC`.
- `object_name` (String) Table, view, or materialized view whose columns are granted; late-binding views do not support column privileges.
- `schema_name` (String) Schema containing the table or view.

### Read-Only

- `id` (String) JSON identity of the observed object, using the same format as the paired resource. Null for a missing relationship.
- `privileges` (Map of Set of String) Current explicit privileges for the selected tuple; inherited privileges are excluded.
<!-- markdownlint-enable MD013 MD022 MD033 -->

`id` (String, computed) is the tuple's JSON identity, using the paired resource's warehouse, provider database,
`database_name`, `schema_name`, `object_name`, `grantee`, and `grantee_type` keys.

No column grants return an empty map; a missing database, relation, or grantee raises an error. Table-level grants are
not column grants and are not returned. No grants are adopted, revoked, or added.
