# redshift_datashare_memberships (Data Source)

Lists, for every schema of the outbound datashares in one producer database and each kind, whether the share holds
every current table and view (`TABLES`) or SQL function overload (`FUNCTIONS`) of the schema, as
`redshift_datashare_membership` and its lookup report it. Does not adopt members, enforce exclusive ownership, or
require a SQL superuser. See AWS
[SVV_DATASHARE_OBJECTS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_DATASHARE_OBJECTS.html).

## Example Usage

```terraform
data "redshift_datashare_memberships" "reporting" {
  database  = "analytics"
  datashare = "reporting"
}

output "incomplete_memberships" {
  value = [for item in data.redshift_datashare_memberships.reporting.datashare_memberships : "${item.schema}/${item.kind}" if !item.all]
}
```

## SQL Statements

Simplified SQL used by the provider to read this data source.

```sql
-- Check that the selected database is local.
SELECT ... FROM svv_redshift_databases WHERE database_name = '...' AND database_type = 'local';

-- List the shared schemas and members of the database's outbound datashares.
SELECT ... FROM svv_datashare_objects WHERE share_type = 'OUTBOUND' AND object_type IN ('schema', 'table', ...) ...;

-- List source tables and views to check coverage.
SELECT ... FROM svv_all_tables WHERE database_name = '...' AND table_type <> 'EXTERNAL TABLE';

-- List source SQL functions to check coverage.
SELECT ... FROM pg_proc_info JOIN pg_namespace ... JOIN pg_language ... WHERE prokind = 'f' AND lanname = 'sql';
```

## Read Behavior

Each shared schema yields one `FUNCTIONS` and one `TABLES` element, ordered by share and schema. Coverage is derived
from these three queries, however many schemas the shares hold. `all` compares counts per qualified name, because the
catalog reports identical name-only rows for overloads; an empty source set is covered. Omit `database` to use the
provider database, `datashare` to list every outbound share of that database, and `schema` to list every shared schema.
Only datashares of that one database are listed; `redshift_datashares` lists the datashares of every database. A
database that does not exist or is not local, such as a datashare consumer database, lists nothing.

The catalog does not quote qualification. A schema whose name contains a period is omitted, as is a kind whose source
objects include a name containing one. A schema with `include_new = true` is listed with its current coverage, which is
no guarantee about future objects.

`id` (String, computed) is the listing's provider-relative JSON identity containing the database and configured filters.

Only rows visible to the provider user are compared, so restricted visibility can report `all = true` without proving
that every source object is shared. Only read-only SQL is executed.
