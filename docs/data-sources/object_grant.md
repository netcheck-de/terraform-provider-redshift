# redshift_object_grant (Data Source)

Reads explicit local database, schema, table (including views), function, procedure, model, or COPY template
privileges, or the privileges common to all current tables, functions, or procedures of a schema. See AWS
[GRANT](https://docs.aws.amazon.com/redshift/latest/dg/r_GRANT.html).

Set `database_type = "shared"` to read a consumer database's `DATABASE`, `SCHEMA`, `TABLE`, or name-wide routine
grants through qualified `SHOW GRANTS` from the administration database. Shared `FUNCTION` and `PROCEDURE` select
the corresponding producer routine kind, omit `arguments`, and use the consumer's FUNCTION ACL readback. Shared
`ALL TABLES`, `ALL FUNCTIONS`, and `ALL PROCEDURES` list distinct members and intersect their individual
`SHOW GRANTS` results, including grant options. `ALL FUNCTIONS` covers all shared routine kinds; `ALL PROCEDURES`
selects procedures only.
Shared routine and snapshot lookups require a SQL superuser so filtered metadata cannot report false absence or an
incomplete common privilege set.

## Example Usage

```terraform
data "redshift_object_grant" "report" {
  database_name = "analytics"
  schema_name   = "reporting"
  object_name   = "daily_summary"
  object_type   = "TABLE"
  grantee       = "report_readers"
  grantee_type  = "GROUP"
}
```

## Schema

### Required

- `database_name` (String) Database containing the object; local unless `database_type = "shared"`.
- `grantee` (String) Receiving identity name; use `public` with `grantee_type = "PUBLIC"`.
- `grantee_type` (String) `ROLE`, `USER`, `GROUP`, or `PUBLIC`.
- `object_type` (String) `DATABASE`, `SCHEMA`, `TABLE` (including views), `FUNCTION`, `PROCEDURE`, `MODEL` (a machine learning model, whose prediction or inference function is granted through it), `TEMPLATE` (a COPY template), or a snapshot of a schema's current objects: `ALL TABLES`, `ALL FUNCTIONS`, or `ALL PROCEDURES`.

### Optional

- `arguments` (String) Comma-separated argument types of a local `FUNCTION` or `PROCEDURE`, such as `INTEGER, VARCHAR`, which select one overload; omit it for a routine without arguments. Shared routine permissions cover every overload of the name, so shared grants must omit this argument. Types are canonicalized and lengths dropped, because Redshift identifies local overloads by type names only.
- `database_type` (String) Set to `shared` for a consumer database created from a datashare; omit for a local database. Shared grants run from the administration database. Shared routines and snapshots require a SQL superuser to prove complete catalog visibility. Routines have name-wide ACLs, so `FUNCTION` and `PROCEDURE` require arguments to be omitted; producer routine kinds distinguish their identities. Shared procedures use the verified FUNCTION ACL syntax, and `ALL PROCEDURES` enumerates current procedure names instead of issuing unsupported native bulk syntax. `ALL FUNCTIONS` covers all shared routine names, including procedures. Object-level access requires WITH PERMISSIONS.
- `object_name` (String) Table, view, function, procedure, model, or template name; required for `TABLE`, `FUNCTION`, `PROCEDURE`, `MODEL`, and `TEMPLATE` only.
- `schema_name` (String) Schema containing the object, or whose objects an `ALL …` snapshot covers; required for every type except `DATABASE`.

### Read-Only

- `grant_option_privileges` (Set of String) Subset of `privileges` that the grantee also holds `WITH GRANT OPTION`, so it can grant them to others. Only a `USER` grantee can hold grant options. Defaults to none. Removing a privilege from this set keeps the privilege and revokes only its grant option; Redshift rejects that while the grantee's own grants depend on it, because the provider never cascades.
- `id` (String) JSON identity of the observed object, using the same format as the paired resource. Null for a missing relationship.
- `privileges` (Set of String) Current explicit privileges for the selected tuple; inherited privileges are excluded.

## SQL Statements

Simplified SQL used by the provider to read this data source.

```sql
-- Read explicit grants on the selected object.
SHOW GRANTS ON ...;

-- Check superuser access for reads that require complete catalog visibility.
SELECT usesuper FROM pg_user WHERE usename = current_user;

-- Read local routine privileges.
SELECT ... FROM svv_function_privileges WHERE namespace_name = '...' ...;

-- Read local relation privileges.
SELECT ... FROM svv_relation_privileges WHERE namespace_name = '...' ...;

-- Read machine learning model privileges.
SELECT ... FROM svv_ml_model_privileges WHERE namespace_name = '...' AND model_name = '...' ...;

-- Enumerate shared tables for a schema snapshot.
SELECT DISTINCT ... FROM svv_all_tables WHERE database_name = '...' AND schema_name = '...';

-- Enumerate shared routines for a schema snapshot.
SELECT DISTINCT ... FROM svv_redshift_functions WHERE database_name = '...' AND schema_name = '...';
```

## Read Behavior

`id` (String, computed) is the permission tuple's JSON identity, using the paired resource's warehouse, provider
database, `database_name`, `database_type`, `schema_name`, `object_name`, `object_type`, `arguments`, `grantee`, and
`grantee_type` keys
that are set. An existing tuple with no explicit privileges still has an ID.

No explicit grants returns an empty set; a missing target or grantee raises an error. Unlike resource reconciliation,
observational reads can include newly introduced privilege names. `grant_option_privileges` lists the privileges a user
holds `WITH GRANT OPTION`. Function and procedure lookups select the overload with `arguments`. No grants are adopted,
revoked, or added.
