# redshift_view (Data Source)

Reads an existing ordinary or late-binding view without managing it. See AWS
[CREATE VIEW](https://docs.aws.amazon.com/redshift/latest/dg/r_CREATE_VIEW.html).

## Catalog Query

```sql
SELECT ... FROM pg_views WHERE schemaname = '...' AND viewname = '...';
```

## Example Usage

```terraform
data "redshift_view" "daily_sales" {
  database = "analytics"
  schema   = "reporting"
  name     = "daily_sales"
}
```

## Schema

### Required

- `database` (String) Local database containing the view.
- `name` (String) View name.
- `schema` (String) Existing schema containing the view.

### Read-Only

- `definition_fingerprint` (String) SHA-256 of the catalog definition with whitespace collapsed; equals the paired resource's `definition_fingerprint` for the same definition.
- `id` (String) JSON identity of the observed object, using the same format as the paired resource. Null for a missing relationship.
- `late_binding` (Boolean) Whether the view is late-binding (`WITH NO SCHEMA BINDING`).
- `owner` (String) SQL user owning the view.
- `query` (String) Catalog definition from `pg_views`, as Redshift prints it.
<!-- markdownlint-enable MD013 MD022 MD033 -->

`id` (String, computed) is the observed view's JSON identity, using the same warehouse, database, schema, and name keys
as the paired resource.

`query` is the catalog's rendering of the definition: the `SELECT` of an ordinary view, and the complete
`CREATE VIEW ... WITH NO SCHEMA BINDING` statement of a late-binding view. A missing view, a missing database, or a
materialized view is an error.
