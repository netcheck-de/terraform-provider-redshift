# redshift_external_partitions (Data Source)

Lists the partitions of the partitioned external tables of one database, the partitions `redshift_external_partition`
manages. See AWS
[SVV_EXTERNAL_PARTITIONS](https://docs.aws.amazon.com/redshift/latest/dg/r_SVV_EXTERNAL_PARTITIONS.html).

## Example Usage

```terraform
data "redshift_external_partitions" "sales" {
  database = "warehouse"
  schema   = "raw"
  table    = "sales"
}

output "sales_partitions" {
  value = { for partition in data.redshift_external_partitions.sales.external_partitions : partition.values.sale_date => partition.location }
}
```

## SQL Statements

Simplified SQL used by the provider to read this data source.

```sql
-- Check that the selected database is local.
SELECT ... FROM svv_redshift_databases WHERE database_name = '...' AND database_type = 'local';

-- Read the partition keys of the selected database's external tables.
SELECT ... FROM svv_external_columns WHERE redshift_database_name = '...' AND schemaname = '...' AND tablename = '...';

-- List the partitions of those tables.
SELECT ... FROM svv_external_partitions WHERE schemaname = '...' AND tablename = '...';
```

## Read Behavior

`database` defaults to the provider's `database`. The `schema` and `table` filters compare without case, as Redshift
folds identifiers. Items are ordered by schema, table, and partition values; no match returns an empty
`external_partitions` list, and the partition read is skipped when no matching table is partitioned. `id` combines the
listed database and configured filters within the warehouse.

`values` maps every partition key, as the catalog names it, to the partition's value. `location` is the catalog's
location, without a folder's trailing slash and truncated to 128 characters. `SVV_EXTERNAL_PARTITIONS` has no database
column, so the partition keys of the listed database's tables decide which partitions belong to it; an equally named
external schema of another database can therefore add partitions with matching keys. The same values with different
locations are ambiguous and fail the read. Without `schema` and `table`, the partition read covers every partition the
provider's SQL identity can see. A database that does not exist or is not local, such as a datashare consumer database,
lists nothing.
