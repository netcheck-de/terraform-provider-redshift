# redshift_template (Data Source)

Reads one COPY template's data format, parameters, and owner as Redshift reports them. See AWS
[SHOW TEMPLATE](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_TEMPLATE.html) and
[SHOW TEMPLATES](https://docs.aws.amazon.com/redshift/latest/dg/r_SHOW_TEMPLATES.html).

## Catalog Query

```sql
SHOW TEMPLATES FROM SCHEMA schema LIKE '...';
SHOW TEMPLATE schema.name;
```

## Example Usage

```terraform
data "redshift_template" "csv_events" {
  database = "analytics"
  schema   = "staging"
  name     = "csv_events"
}

output "csv_events_parameters" {
  value = data.redshift_template.csv_events.parameters
}
```

## Schema

### Required

- `database` (String) Local database containing the template; templates cannot be referenced from other databases.
- `name` (String) Template name.
- `schema` (String) Existing schema containing the template.

### Read-Only

- `format` (String) Data format of `FORMAT AS`, such as `JSON`; null for pipe-delimited text.
- `format_argument` (String) Argument of the format, such as `auto` for `JSON 'auto'`; null without one.
- `id` (String) JSON identity of the observed object, using the same format as the paired resource. Null for a missing relationship.
- `owner` (String) SQL user owning the template.
- `parameters` (Map of String) COPY parameters keyed by their UPPERCASE keyword, as `SHOW TEMPLATE` prints them, with `""` for keywords without an argument; null when the template has none.
<!-- markdownlint-enable MD012 MD013 MD022 MD033 -->

`id` (String, computed) is the template's JSON identity, using the paired resource's warehouse, `database`, `schema`,
and `name` keys. A missing database, schema, or template fails the lookup, and so does a parameter the provider does
not know. Reading a template requires `USAGE` on it and on its schema, or a superuser.
